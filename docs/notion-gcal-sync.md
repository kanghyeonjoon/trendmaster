# 노션 ↔ 구글캘린더 업무시간 양방향 동기화

Make(make.com) 시나리오로 구축된 노션-구글캘린더 양방향 동기화 시스템 문서입니다.
업무 일정을 노션 또는 구글캘린더 어느 쪽에서 입력하든 양쪽에 반영되고,
노션 DB에 쌓인 데이터로 **카테고리별 업무시간을 집계·분석**할 수 있습니다.

## 구성 요소

| 리소스 | ID / 위치 |
|---|---|
| 노션 DB "업무 시간 기록" | `ec981812-3a80-418c-b568-80803f7a0125` (CRM 페이지 하위) |
| 노션 데이터소스 | `9b001160-b103-41cd-af7b-3382e6a7e84a` |
| 구글 "업무" 캘린더 | `6b864b57...d26742@group.calendar.google.com` |

| Make 시나리오 B | `9580817` 구글캘린더 → 노션 |
| Make 노션 연결 | `13368489` (notion2) |
| Make 구글 연결 | `14466643` "Google Calendar (노션 동기화)" |

## 노션 DB 스키마

| 속성 | 타입 | 용도 |
|---|---|---|
| 이름 | title | 일정 제목 (캘린더 이벤트 제목과 동기화) |
| 일정 | date (시작~종료) | 업무 시간 범위. **시간까지 입력해야 동기화됨** (날짜만 입력 시 제외) |
| 카테고리 | select | 회의/개발/기획/콘텐츠/학습/이동/기타 — 시간 분석의 기준 축 |
| 메모 | rich_text | 상세 내용 (이벤트 설명에 포함) |
| GCal Event ID | rich_text | 동기화 매핑 키 — **직접 수정 금지** |
| 소요시간(h) | formula | `dateBetween(end(일정), start(일정), "minutes") / 60` 자동 계산 |

## 동작 방식

두 시나리오 모두 **12시간 간격**(하루 2회)으로 실행됩니다. Make Free 플랜의
월 1,000 오퍼레이션 한도 내에서 안정적으로 동작하는 주기입니다.

### 시나리오 A: 노션 → 구글캘린더

1. `Search Objects` — 최근 수정순으로 항목 조회 후, **최근 13시간 내 수정된 항목만** 필터로 통과
   (12시간 실행 간격과 1시간 겹치게 잡아 누락 방지. watch 트리거는 API로 생성 시
   epoch 미초기화로 동작하지 않아 검색 기반으로 설계)
2. 라우터 분기:
   - **GCal Event ID 없음** → 캘린더에 이벤트 생성 → 생성된 Event ID를 노션에 역기록
   - **GCal Event ID 있음** → 해당 이벤트를 노션 값으로 업데이트
3. 종료 시간이 비어 있으면 시작 +1시간으로 생성. 날짜 값은 `parseDate`로 변환해 전달

### 시나리오 B: 구글캘린더 → 노션

1. `Watch Events` — 업무 캘린더에서 수정된 이벤트 감지 (기본 이벤트 타입만, 삭제 제외)
2. 노션에서 GCal Event ID로 기존 항목 검색 → Text Aggregator로 존재 여부 판정
   (검색 결과가 0건이어도 빈 텍스트 번들이 나와 라우팅이 끊기지 않음)
3. 제목·시작시간까지 일치하는지 2차 검색 → Text Aggregator로 내용 일치 여부 판정
4. 라우터 분기:
   - **노션에 없음** → 새 항목 생성, 일정은 시간 포함(`includeTime`) 저장 (카테고리는 "기타"로 — 노션에서 직접 지정)
   - **있지만 내용 다름** → 노션 항목 업데이트
   - **내용 동일** → 스킵 (무한 루프 방지)

### 루프 방지 설계

- B는 제목·시작시간이 이미 일치하면 쓰기를 하지 않으므로, A→B→A 핑퐁이 한 사이클 내 수렴
- A는 "수정된 항목"만 처리하므로 대기 상태에서는 오퍼레이션을 거의 소비하지 않음

## 업무시간 분석 지표 활용법

노션 DB에서 뷰만 추가하면 바로 지표가 나옵니다:

1. **카테고리별 시간 집계**: 표 뷰 → 그룹화: 카테고리 → 소요시간(h) 열의 계산: 합계(Sum)
   → "이번 주 회의에 12.5h, 개발에 20h" 식의 객관적 수치 확인
2. **주간/월간 추이**: 뷰 필터 "일정: 이번 주" / "이번 달" 복제 뷰 생성
3. **캘린더 뷰**: 일정 속성 기준 캘린더 뷰로 시간 배분 시각화
4. **개선 포인트 찾기**: 카테고리별 비중이 목표와 다른 곳(예: 회의 비중 과다)을 주 단위로 비교

## 제약 및 주의사항

- **동기화 주기 12시간**: 실시간이 아닙니다. 즉시 동기화가 필요하면 Make에서 해당 시나리오 "Run once" 실행
- **시간 미포함 일정은 동기화 제외**: 노션에서 날짜만 입력한 항목은 캘린더로 넘어가지 않음
- **캘린더에서 제목만 수정한 경우**: 기존 항목의 제목 변경은 시작시간이 같으면 노션에 반영되지 않을 수 있음 (시간 변경은 반영됨). 제목 수정은 노션에서 하는 것을 권장
- **삭제는 동기화되지 않음**: 한쪽에서 삭제해도 반대쪽에 남습니다. 양쪽에서 각각 삭제 필요
- **노션 검색 인덱스 지연**: 항목 생성 직후 1~2분간 검색에 안 잡힐 수 있음. 12시간 간격
  운영에서는 영향 없지만, Make에서 시나리오를 수동으로 연속 실행하면 드물게 중복이 생길 수
  있음 — 중복 항목은 노션에서 삭제하면 됨
- **Make Free 플랜**: 활성 시나리오 2개 한도를 동기화 A·B가 모두 사용 중. 기존 시나리오
  "영상 기획안·대본 자동 생성"(9490086), "CRM 대시보드 → SOLAPI"(9372834)는 비활성화됨 —
  다시 켜려면 동기화 시나리오를 끄거나 유료 플랜 필요

## 문제 해결

- **동기화가 안 될 때**: Make → Scenarios → 해당 시나리오 → History에서 실행 로그 확인
- **구글 인증 만료**: Make → Connections → "Google Calendar (노션 동기화)" 재인증
- **노션 권한 문제**: 노션에서 DB 페이지 → ⋯ → 연결 → `notion2` 통합이 연결되어 있는지 확인
